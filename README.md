# 🎧 BeatLab Bot

Telegram-бот для битмейкеров: полезные инструменты, библиотека сэмплов и биржа совместной работы.
Написан на **Bun + TypeScript**.

## Стек

| Компонент | Технология |
|---|---|
| Рантайм | [Bun](https://bun.sh) |
| Язык | TypeScript (strict) |
| Bot API | [grammY](https://grammy.dev) |
| ORM | [Drizzle](https://orm.drizzle.team) + `bun:sqlite` |
| Валидация | [Zod](https://zod.dev) |

## Быстрый старт

```bash
# 1. Установить зависимости
bun install

# 2. Настроить окружение
cp .env.example .env   # вписать BOT_TOKEN и WEB_APP_URL

# 3. Применить миграции БД
bun run db:migrate

# 4. Запустить
bun run dev            # watch-режим
# или
bun run start          # обычный запуск
```

### 🎵 BPM & Key — внутри мини-приложения

Все инструменты живут в **Mini App** (`/start` → «🎧 Открыть BeatLab»).
Анализатор запускается прямо в браузере пользователя:

- ⏱ **темп** в BPM (±2, с октавной нормализацией в диапазон 70–180)
- 🎹 **тональность** и её номер в **Camelot-нотации** (например `A minor → 8A`)
- 📊 **уверенность** определения ключа (0–100%)

Как это работает:

1. Пользователь перетаскивает трек в мини-приложение
2. Файл декодируется через **Web Audio API** (`decodeAudioData`) — mp3, wav, ogg, m4a, flac, aac из коробки, без сервера
3. Общий анализатор (`shared/analyze.ts`):
   - **BPM** — огибающая энергии (onset envelope) + автокорреляция с подбором октавы
   - **Ключ** — хромаграмма через FFT → корреляция с профилями Крумхансла–Шмуклера
4. Всё считается на устройстве — трек никуда не загружается

## Мини-приложение

```bash
bun run up         # поднимает всё разом: web-сервер + HTTPS-туннель + бот
```

Что делает `bun run up`:

1. собирает бандл мини-приложения (если его ещё нет)
2. запускает статический сервер на `http://localhost:3000`
3. открывает **HTTPS-туннель** через SSH (localhost.run) и прописывает
   свежий адрес в `WEB_APP_URL` (.env)
4. перезапускает бота с новым адресом

Логи — в `.up-logs/`. Домен туннеля меняется при каждом запуске, поэтому
адрес в `.env` обновляется автоматически.

Поштучно (если нужно):

```bash
bun run web:build  # сборка бандла (web/main.ts → web/public/main.js)
bun run web:serve  # статический сервер на http://localhost:3000
```

## Структура проекта

```
src/
├── index.ts          # точка входа, long polling
├── bot.ts            # создание бота и роутинг команд
├── config.ts         # конфигурация окружения (Zod)
├── types.ts          # общий контекст и утилиты
├── handlers/         # обработчики команд
├── keyboards/        # клавиатуры
├── web/
│   └── server.ts     # статический сервер мини-приложения
└── db/
    ├── schema.ts     # схема таблиц (Drizzle)
    ├── index.ts      # подключение к SQLite
    ├── users.ts      # запросы к таблице users
    ├── migrate.ts    # ручной раннер миграций
    └── migrations/   # SQL-миграции (*.sql)

shared/               # общий код бота и мини-приложения
├── analyze.ts        # детект BPM и тональности
└── fft.ts            # radix-2 FFT

web/
├── main.ts           # UI мини-приложения (TypeScript)
├── tsconfig.json     # DOM-типы для фронтенда
└── public/           # index.html, style.css, main.js (build output)

tests/
├── helpers.ts        # синтез тестового сигнала + WAV/MP3-энкодеры
└── analyze.test.ts   # проверка BPM/Key на заведомо известных сигналах
```

## Окружение (.env)

| Переменная | Описание |
|---|---|
| `BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
| `WEB_APP_URL` | HTTPS-адрес мини-приложения (кнопка «Открыть BeatLab») |
| `BOT_USERNAME` | Юзернейм бота без `@` (необязательно) |
| `DB_PATH` | Путь к файлу SQLite (по умолчанию `./beatlab.db`) |

## Миграции

SQL-файлы кладутся в `src/db/migrations/` с порядковым номером:

```
0001_init.sql
0002_samples.sql
```

Применить: `bun run db:migrate`.
